# 三位助教分工与交叉试跑安排

## 助教 A：集成、发布与最终复验

- 维护仓库结构、版本清单、环境脚本和学生/助教包隔离。
- 汇总 B、C 的数据、Schema、参考结果和问题修复。
- 统一发布模块检查点，避免多个版本并行流传。
- 在空输出目录执行 M6 全链试跑，核对冻结指标和发布清单。

## 助教 B：M1-M3 主责

- M1 流程模板、接口摘要和内部正确流程图。
- M2 OpenSky 解析、41 字节帧、定点量化、标志位、校验和、错误样例及检查点。
- M3 九帧数据、单源多时刻关联、当前态势和 SQLite 选做路径。
- 完成后由未参与相应材料编写的助教 C 按学生身份试跑。

## 助教 C：M4-M5 主责

- M4 双格式字段定义、候选映射、人工核验依据、正式映射和统一消息样例。
- M5 四类固定规则、异常样例、预期告警数量和质量态势。
- 完成后由未参与相应材料编写的助教 B 按学生身份试跑。

## 共同规则

- 模块主责人不能作为该模块唯一试跑人。
- 问题统一记入 `issue_log.csv`，修复后必须补自动化测试或明确人工复验步骤。
- 冻结后只修复阻断性错误，不新增工具链、数据、算法或工程环节。
- 学生包不得包含 `ta_reference_package/`、内部 case ID、预期告警数量或完整参考实现。
